# Rule: Frontend UI

Apply to React, TypeScript, styling, and UI tasks.

- Follow the relevant design reference image and feature README.
- Use React + TypeScript + Vite, Tailwind CSS, shadcn/ui, and Lucide as established by the project.
- Prefer existing shared components and design tokens.
- Keep page layout, feature logic, API calls, and reusable UI components separated.
- All visible controls must have a defined and working action.
- Provide loading, empty, error, and success states where relevant.
- Use accessible labels, keyboard interaction, focus states, and sensible contrast.
- Do not use decorative AI gradients, robot mascots, or chatbot-first layouts.
- Do not hardcode production data. Keep temporary mock data isolated behind a mock service or development-only adapter.
- Do not access local files directly from React. Use the backend API or approved Tauri bridge.
- Do not claim an action succeeded until the backend confirms success.
- Avoid oversized components and duplicated UI logic.
