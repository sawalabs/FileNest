# Rule: Project Baseline

Apply to all tasks.

- Inspect the existing repository before creating or changing files.
- Follow `design/AGENT_INSTRUCTIONS.md` and the target feature README.
- Preserve the agreed stack. Do not replace frameworks or major libraries without approval.
- Keep implementation minimal, modular, and scoped to the requested task.
- Reuse existing components, hooks, services, schemas, repositories, and utilities.
- Do not create duplicate abstractions or speculative infrastructure.
- Do not invent requirements, API endpoints, configuration keys, files, or test results.
- If a requirement is ambiguous and materially affects behavior, ask one focused clarification.
- Do not silently change behavior in unrelated features.
- Keep user-facing UI conventional and utility-focused; AI is an implementation capability, not the visual identity of the product.
- Only manually registered Managed Folders are in scope.
- Report assumptions and unresolved dependencies explicitly.
